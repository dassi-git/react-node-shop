# רשימת בדיקות לפני עלייה לאוויר

מטרת המסמך היא לוודא שמערכת הזמנות עיצובי הפירות מוכנה לשימוש אמיתי. יש לסמן כל סעיף רק לאחר שבוצע ונבדק בסביבת staging הדומה לייצור.

## 1. הכנת סביבה ופריסה

- [ ] קיימת סביבת `production` נפרדת מסביבת `development`.
- [ ] השרת עולה ללא שימוש ב־MongoDB בזיכרון.
- [ ] `DATABASE_URI` מצביע למסד נתונים מנוהל ומאובטח.
- [ ] מוגדר `NODE_ENV=production`.
- [ ] מוגדר `PORT` דרך משתנה סביבה.
- [ ] מוגדר `CLIENT_URL` לכתובת האתר האמיתית.
- [ ] מוגדר דומיין עם HTTPS פעיל.
- [ ] ה־Frontend משתמש בכתובת API של production ולא ב־localhost.
- [ ] אין סודות בקוד, ב־Git או בקבצי build.
- [ ] קבצי `.env` אינם מועלים ל־GitHub.
- [ ] קיימת תצורת CORS שמאפשרת רק את דומייני האתר.
- [ ] נבדקה פריסה נקייה על שרת חדש.
- [ ] קיימת תוכנית rollback לגרסה הקודמת.

## 2. בדיקות הרשמה והתחברות

- [ ] הרשמה עם נתונים תקינים יוצרת משתמש אחד בלבד.
- [ ] הרשמה עם אימייל קיים מחזירה הודעה ברורה.
- [ ] הרשמה עם שם משתמש קיים מחזירה הודעה ברורה.
- [ ] סיסמה קצרה נדחית גם בצד הלקוח וגם בצד השרת.
- [ ] אימייל לא תקין נדחה.
- [ ] מספר טלפון לא תקין נדחה.
- [ ] התחברות עם פרטים תקינים יוצרת token תקף.
- [ ] התחברות עם סיסמה שגויה נכשלת בלי לחשוף מידע מיותר.
- [ ] התחברות עם משתמש לא קיים מחזירה תשובה כללית.
- [ ] token שפג תוקפו מסיר את המשתמש מהמערכת ומעביר להתחברות.
- [ ] משתמש רגיל אינו יכול לגשת למסכי מנהל.
- [ ] משתמש רגיל אינו יכול לקרוא או לשנות נתונים של משתמש אחר.
- [ ] מנהל יכול לגשת רק לפעולות מנהל שהוגדרו.
- [ ] התנתקות מוחקת את token מהדפדפן.
- [ ] ניסיון גישה ללא token מחזיר `401`.
- [ ] נבדקו ניסיונות רבים של התחברות ונחסמו לפי rate limit.

## 3. איפוס סיסמה ומיילים

- [ ] בקשת איפוס עם אימייל תקין מחזירה תשובה כללית.
- [ ] המערכת אינה חושפת אם אימייל קיים או לא.
- [ ] קישור איפוס תקף למשך שעה בלבד.
- [ ] token איפוס חד־פעמי נמחק לאחר שימוש.
- [ ] token שגוי או שפג תוקפו נדחה.
- [ ] סיסמה חדשה עומדת בכללי האבטחה.
- [ ] סיסמאות ישנות אינן נשמרות בלוגים.
- [ ] פרטי SMTP נמצאים רק במשתני סביבה.
- [ ] שליחת מייל נכשלת בצורה מבוקרת ואינה מפילה את השרת.
- [ ] נבדקה שליחת מייל בסביבת staging.
- [ ] קיימת תבנית מייל תקינה בעברית ובמובייל.

## 4. מוצרים ומלאי

- [ ] רשימת המוצרים נטענת בהצלחה.
- [ ] מצב API תקול מוצג כשגיאת חיבור ולא כרשימה ריקה.
- [ ] מסד נתונים ריק מוצג בצורה ברורה למשתמש.
- [ ] מוצר מוצג עם שם, מחיר, תמונה, תיאור וקטגוריה.
- [ ] מוצר ללא תמונה אינו שובר את העיצוב.
- [ ] מוצר שאזל מהמלאי אינו ניתן להוספה לסל.
- [ ] מוצר במלאי נמוך מציג אזהרה מתאימה.
- [ ] מנהל בלבד יכול ליצור מוצר.
- [ ] מנהל בלבד יכול לעדכן מוצר.
- [ ] מנהל בלבד יכול למחוק מוצר.
- [ ] העלאת תמונה מוגבלת לסוגי קבצים מותרים ולגודל מרבי.
- [ ] שמות, מחירים וסטטוס מלאי עוברים validation בצד השרת.
- [ ] מחיקת מוצר שנמצא בהזמנות קיימות אינה שוברת היסטוריית הזמנות.
- [ ] seed של development אינו מוחק מידע קיים.

## 5. סל הקניות

- [ ] משתמש לא מחובר מועבר להתחברות בעת כניסה לסל.
- [ ] סל חדש נטען כרשימה ריקה ולא כשגיאת `404`.
- [ ] הוספת מוצר יוצרת סל אם עדיין אין סל למשתמש.
- [ ] הוספת אותו מוצר מגדילה כמות במקום ליצור שורה כפולה.
- [ ] אי אפשר להוסיף מוצר שאזל מהמלאי.
- [ ] הגדלת כמות מעדכנת את השרת ואת המסך.
- [ ] הקטנת כמות מעדכנת את השרת ואת המסך.
- [ ] מחיקת מוצר מסירה רק את המוצר הנבחר.
- [ ] ריקון הסל עובד גם כאשר קיימים מספר מוצרים.
- [ ] שגיאת API בסל מוצגת עם כפתור ניסיון חוזר.
- [ ] המחירים והכמויות מחושבים מחדש ולא מסתמכים על ערך תצוגה בלבד.
- [ ] לאחר יצירת הזמנה, הסל מתנקה רק אם יצירת ההזמנה הצליחה.

## 6. הזמנה מותאמת אישית

- [ ] רק משתמש מחובר יכול לשלוח בקשת הצעת מחיר.
- [ ] הזמנה מהסל כוללת את כל המוצרים שנבחרו.
- [ ] כל מוצר כולל מזהה, שם, כמות, מחיר יחידה ומחיר כולל.
- [ ] הכמות מוגבלת לערך חיובי וסביר.
- [ ] מחירים שליליים או חריגים נדחים בצד השרת.
- [ ] עיר וכתובת חובה לפני שליחה.
- [ ] תאריך משלוח נשמר בפורמט תקין.
- [ ] הערות הלקוח נשמרות בהזמנה.
- [ ] סל שלא נטען אינו הופך אוטומטית לפריט דמה.
- [ ] בקשה ללא פריטים מוצגת למשתמש ונחסמת.
- [ ] לאחר שליחה מוצג מספר הזמנה.
- [ ] לאחר שליחה הלקוח מועבר ל־"ההזמנות שלי".
- [ ] הלקוח רואה את ההזמנה שנשלחה בהיסטוריית ההזמנות.
- [ ] המנהל מקבל את ההזמנה ברשימת ההזמנות הממתינות.

## 7. הצעות מחיר

- [ ] רק מנהל יכול ליצור הצעת מחיר.
- [ ] מנהל רואה את כל פריטי ההזמנה.
- [ ] מנהל רואה כתובת, תאריך והערות לקוח.
- [ ] מחיר הצעה חייב להיות מספר חיובי או אפס לפי החלטת העסק.
- [ ] דמי משלוח עוברים validation.
- [ ] מקדמה אינה גבוהה מסכום ההצעה.
- [ ] להצעה יש תאריך תפוגה.
- [ ] הצעה פגה אינה ניתנת לאישור.
- [ ] הצעה שנדחתה אינה ניתנת לאישור מחדש.
- [ ] לא ניתן ליצור הצעות כפולות להזמנה שכבר קיבלה הצעה פעילה.
- [ ] הלקוח רואה את מחיר ההצעה, המשלוח, המקדמה וההערות.
- [ ] הלקוח יכול לאשר הצעה ששייכת אליו בלבד.
- [ ] הלקוח יכול לדחות הצעה ששייכת אליו בלבד.
- [ ] אישור הצעה מעביר את ההזמנה ל־`quote_accepted`.
