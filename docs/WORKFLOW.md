# מסלול עבודה מקצועי

## מטרת המסמך

זהו מסמך העבודה המרכזי להמשך הפרויקט. בתחילת כל שיחה יש לקרוא אותו יחד עם
`docs/TEST_RESULTS.md`, ולאתר את המשימה הראשונה הפתוחה בעדיפות הגבוהה ביותר.

## מצב יעד

המטרה הקרובה היא להגיע לגרסה מקצועית ויציבה לתיק עבודות ול־staging. אין להוסיף
פיצ'ר חדש לפני שהמסלול העסקי הקיים עובד ונבדק מקצה לקצה:

`Register → Login → Product → Basket → Quote Request → Admin Quote → Approval → Payment`

## סדר עדיפויות

### P0 - חסימות ואמינות

- לתקן כל כשל שמונע `npm test`, `npm run build` או הפעלה מקומית.
- להשלים תרחיש משתמש מלא מול MongoDB.
- לסגור את תרחיש Stripe Test או לתעד במפורש מדוע הוא חסום.
- תשלומי Stripe/PayPal ייבדקו ויוגדרו מחדש לפני העלייה לענן; כרגע החיבור החיצוני חסום כי העסק עדיין אינו רשום ואין credentials.
- לוודא שהשרת לא מסתמך על נתוני מחיר, הרשאה, בעלות או מלאי מהלקוח.

### P1 - איכות מקצועית

- להוסיף בדיקות integration ל־auth, basket, orders, quotes ו־payments.
- להוסיף בדיקות הרשאות למשתמש רגיל ולמנהל.
- להוסיף בדיקות כשל: מלאי, תשלום כפול, token שפג, מוצר חסר ו־webhook חוזר.
- להוסיף transaction או מנגנון עקבי לעדכון מלאי ויצירת הזמנה.
- להוסיף idempotency ליצירת תשלום ולעדכון סטטוס תשלום.

### P2 - גימור production

- להשלים נגישות, pagination, indexes, ביצועים ו־mobile checks.
- להגדיר staging, HTTPS, secrets, backups, monitoring ו־rollback.
- לנקות שמות קבצים וקומפוננטות, וליישר את התיעוד לגרסאות בפועל.

## Definition of Done

משימה נחשבת גמורה רק כאשר כל הסעיפים הבאים מתקיימים:

1. ההתנהגות הרצויה קיימת בקוד.
2. נתוני קלט לא אמינים נבדקים בצד השרת.
3. קיים טיפול ב־loading, empty, error ו־success במקום הרלוונטי.
4. נוסף או עודכן test ממוקד, או שנרשמה סיבה ברורה לכך שאין אפשרות לבדוק אוטומטית.
5. עברו בדיקות ממוקדות של הקוד שנגעו בו.
6. `git diff --check` עובר.
7. `docs/TEST_RESULTS.md` עודכן רק עם פקודה ותוצאה אמיתית.

## תבנית עבודה לכל משימה

לפני עריכה:

- **בעיה:** מה לא עובד או מה חסר.
- **עוגן:** קובץ, route, controller, component או test שמחליט את ההתנהגות.
- **השערה:** מה גורם לבעיה.
- **בדיקה מפריכה:** פקודה או test זולים שיכולים להוכיח שההשערה שגויה.

אחרי עריכה:

- להריץ קודם את הבדיקה הממוקדת ביותר.
- לתקן רק את אותה שכבה אם הבדיקה נכשלת.
- להריץ בדיקת regression קצרה.
- לתעד מה השתנה, מה נבדק ומה נשאר פתוח.

## תבנית פתיחת שיחה

אפשר להדביק בתחילת שיחה חדשה:

```text
פתח את docs/WORKFLOW.md ואת docs/TEST_RESULTS.md.
הצג את המשימה הראשונה הפתוחה לפי P0/P1/P2.
בדוק קודם את העוגן המקומי ואת הבדיקה הממוקדת ביותר.
בצע את השינוי, הרץ אימות, ועדכן את המסמכים רק לפי תוצאה אמיתית.
אל תיגע במשימות שאינן נדרשות כדי לסגור את המשימה הנוכחית.
```

## תבנית סיום שיחה

כל סיום עבודה צריך להשאיר ארבעה דברים:

- **הושלם:** קבצים והתנהגות.
- **נבדק:** פקודות ותוצאות.
- **נשאר:** חסימות או משימות פתוחות.
- **הצעד הבא:** משימה אחת בלבד, עם קובץ או בדיקה יעד.

## כלל ניהול תיעוד

`WORKFLOW.md` מגדיר את שיטת העבודה, `ROADMAP.md` מגדיר את הכיוון העסקי,
ו־`TEST_RESULTS.md` מכיל ראיות לבדיקות. אין לסמן סעיף כ־PASS או כ־FIXED ללא
פקודה, תוצאה או בדיקה ידנית מתועדת.
